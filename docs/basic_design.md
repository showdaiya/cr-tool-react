# 基本設計書（第1版）

## 1. ドキュメント概要
- **目的**: 既存の Clash Royale ダメージ計算ツールを再構築するにあたり、再実装範囲と高レベルな仕様・構造を共有する。
- **対象読者**: プロダクトオーナー、UI/UX デザイナー、フロントエンドエンジニア。
- **前提と制約**:
  - フロントエンドは React + TypeScript + Vite を使用する。
  - UI コンポーネントライブラリとして Chakra UI を採用する。
  - ブラウザのみで完結するクライアントサイドアプリケーション（バックエンド API なし）。
  - Clash Royale のカードデータはローカル JSON（`CardData.json`）を参照する。

## 2. 現行機能の整理
- 防衛側ユニットの HP 表示。
- 攻撃カードの複数追加、攻撃回数設定、合計ダメージのリアルタイム計算。
- 防衛側カード・攻撃側カードともにカード選択モーダルから切り替え。
- カード画像、名前、HP、ダメージなどの主要ステータス表示。

## 3. 再構築で目指す姿
- SPA 構成で 1 ページに防衛側・攻撃側 UI を集約。
- グローバルステート管理でカードデータ・選択状態を一元管理。
- リアルタイム計算により入力変更と同時に結果を更新。
- モバイルを含むレスポンシブ対応。

## 4. 画面仕様（基本）
### 4.1 レイアウト
- 固定ヘッダー: アプリタイトルを表示。
- メインコンテンツ領域:
  - 左上（PC 時）/ 上部（SP 時）: 防衛カードパネル。
  - 下部: 攻撃カードセクション。追加ボタンと攻撃カードカード群。
- 背景は淡色、カードは白ベースのパネル。

### 4.2 防衛カードパネル
- 表示項目: カード画像、HP、被ダメージ、残り HP。
- 操作: 「選択」ボタンでカード選択モーダルを表示。

### 4.3 攻撃カードリスト
- 表示項目: カード画像、単発ダメージ、攻撃回数、総ダメージ。
- 操作: カードごとに「選択/編集」ボタンでモーダルを表示。
- 追加: カード追加ボタン（+）で攻撃カード行を増やす。

### 4.4 モーダル共通仕様
- オーバーレイ付き中央表示、閉じるボタンあり。
- プルダウンでカード一覧から選択。
- 攻撃カードモーダルでは攻撃回数の数値入力・増減ボタンを提供。

## 5. データ構造（概念）
- **TroopCard**: `EnName`, `JpName`, `Hitpoints`, `Damage`, `Type`, `Icon`。
- **SpellCard**: `EnName`, `JpName`, `Damage`, `TowerDamage`, `Type`, `Icon`。
- **AttackCard**: `CardKey`, `Type`, `AttackNumber`。
- **カード辞書**: Troops / Spells の連想配列。

## 6. 状態管理方針
- `CardContext` を用いて以下をグローバル管理。
  - `troops`, `spells`: 参照専用。
  - `defenseCard`: 選択中の防衛カード。
  - `attackCards`: キーにインデックスを持つ攻撃カードの辞書。
  - `attackLastIndex`: 追加操作時に利用するシーケンス番号。
- 再構築時も Context or 代替（Redux Toolkit など）を用い、一貫性のある API を定義。

## 7. 機能要求（高レベル）
1. **防衛カード選択**
   - カード一覧から 1 枚選択。選択状態を保持。
2. **攻撃カード追加/編集/削除**
   - 追加で新しい攻撃カードスロットを作成。
   - 選択モーダルでカード種別（Troop / Spell）と攻撃回数を設定。
   - （再構築時に削除機能の有無を要検討。現状は未実装。）
3. **ダメージ計算**
   - 各攻撃カードの総ダメージ = `Damage × AttackNumber`。
   - 被ダメージ合計 = 各攻撃カードの総ダメージ合計。
   - 残り HP = 防衛カード HP - 被ダメージ合計（0 未満は 0 とする想定）。
4. **UI 表示更新**
   - 状態更新に応じて数値をリアルタイム表示。

## 8. 非機能要求
- パフォーマンス: ローカルデータのみでレスポンス即時。
- アクセシビリティ: モーダルフォーカス管理、ボタンのキーボード操作可能。
- コード品質: TypeScript による型安全性、ESLint/Prettier（既存設定）で静的解析。
- テスト: ユニットテスト（React Testing Library）と E2E テスト（余裕があれば）を視野。
